# Системы интернет вещей — домашние задания

Учебные проекты по дисциплине **«Системы интернет вещей»**: управление устройствами на ESP8266, HTTP и MQTT, сбор показаний DHT11, обновление прошивки по Wi-Fi и интеграции с Tuya и ВКонтакте.

Работы независимы друг от друга. Нумерация сохранена по исходным файлам; здесь представлены задания № 2, 3, 4, 6, 10, 12 и 13, а также дополнительные проекты OTA и VK-бота.

## Запуск скетчей ESP8266

1. Установите Arduino IDE и поддержку плат **esp8266 by ESP8266 Community** через менеджер плат. Адрес индекса: `https://arduino.esp8266.com/stable/package_esp8266com_index.json`.
2. Выберите свою плату, например **NodeMCU 1.0 (ESP-12E Module)**, и USB-порт.
3. Установите библиотеки для нужного задания:

   | Задание | Дополнительные библиотеки |
   | --- | --- |
   | 2, 4, OTA | Достаточно библиотек из пакета ESP8266 |
   | 3 | `DHT11` автора Dhruba Saha с заголовком `DHT11.h` и методом `readTemperatureHumidity` |
   | 6 | `PubSubClient` |
   | 10 | `PubSubClient`, `SimpleDHT` |

   В работе № 3 и работе № 10 используются разные библиотеки для DHT11; они не взаимозаменяемы. Локально для MQTT и метеостанции использовались `PubSubClient 2.8` и `SimpleDHT 1.0.15`.

4. В папке выбранного скетча скопируйте `secrets.example.h` в `secrets.h` и укажите Wi-Fi:

   ```cpp
   #pragma once
   #define WIFI_SSID "YOUR_WIFI_SSID"
   #define WIFI_PASSWORD "YOUR_WIFI_PASSWORD"
   ```

   Файл `secrets.h` исключён из Git. Для каждого скетча нужен свой экземпляр файла.

5. Проверьте адреса в скетче: `serverIP` в № 2, `slave_ip` у ведущей платы № 4, `mqtt_server` в обеих платах № 6, `OTA_SERVER_HOST` в OTA-проекте.
6. Подключите компоненты по [таблице GPIO](docs/hardware.md), откройте `.ino` и загрузите его на плату. Скорость Serial Monitor — **115200 бод**.

### Как проверить задания

- **№ 2:** прошейте две платы, задайте IP второй в `serverIP`. Запросы `http://<IP>/LED=ON` и `http://<IP>/LED=OFF` меняют состояние встроенного светодиода; кнопка отправляет команду второй плате.
- **№ 3:** откройте `http://<IP>/get_temp`. Успешный ответ содержит `temperature` и `humidity`.
- **№ 4:** сначала подключите ведомую плату, укажите её IP в `slave_ip` ведущей. Ведущая плата отправляет `POST /state` со строкой из трёх символов `0`/`1` в порядке R, Y, G. Кнопка ведущей меняет режим светофора.
- **№ 6:** запустите MQTT-брокер на порту `1883`, укажите его адрес в обеих платах. Ведущая публикует состояния R, Y, G в `outTopic`, ведомая подписывается на этот топик.
- **№ 10:** метеостанция публикует данные раз в пять секунд. При отсутствии Wi-Fi или удержании кнопки конфигурации более двух секунд запускает точку `ESP_Config`; веб-форма доступна по `192.168.4.1`, демонстрационный пароль точки — `12345671`. Настройки сохраняются в EEPROM. Для ArduinoOTA первая прошивка загружается через USB.

### MQTT метеостанции № 10

| Топик | Направление относительно платы | Данные |
| --- | --- | --- |
| `weather/station/temperature` | Публикация | Температура |
| `weather/station/humidity` | Публикация | Влажность |

## Python и облачные сервисы

Для Python-проектов создавайте отдельное виртуальное окружение в папке соответствующего задания. Например:

```bash
cd labs/12-tuya-device
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env` своими значениями, затем загрузите переменные в текущую оболочку и запустите скрипт:

```bash
set -a
source .env
set +a
python device.py
```

Команды выше предназначены для Bash/Zsh на macOS/Linux. Скрипты читают переменные окружения; `.env` автоматически не загружается. Для Windows можно задать те же переменные через PowerShell.

| Проект | Переменные окружения | Запуск |
| --- | --- | --- |
| № 12 | `TUYA_PRODUCT_ID`, `TUYA_UUID`, `TUYA_AUTH_KEY` | `python device.py` |
| № 13 | `TUYA_ACCESS_ID`, `TUYA_ACCESS_KEY`, `TUYA_DEVICE_ID` | `python control.py` |
| VK-бот | `VK_GROUP_TOKEN`, `ADMIN_VK_ID` | `python bot.py` |

В каждой папке есть собственные `requirements.txt` и `.env.example`.

Для № 12 создайте продукт и устройство в Tuya, запустите `device.py` и отсканируйте QR-код для привязки. Скрипт обрабатывает DP `104` и подтверждает его значениями `104` и `a`: они должны соответствовать модели вашего продукта. Данные активации SDK сохраняет в локальный `storage.json`.

Для № 13 проверьте `ENDPOINT` в `control.py`: он должен соответствовать региону облачного проекта. Скрипт отправляет `True`, через две секунды — `False`. Имя свойства в `payload["properties"]` сохранено из исходной модели Tuya; перед запуском сопоставьте его с моделью своего устройства.

Названия Python-пакетов для Tuya сверены с документацией [TuyaOS Link SDK](https://github.com/tuya/tuyaos-link-sdk-python) и [Tuya Connector](https://github.com/tuya/tuya-connector-python).

## Локальные настройки

В репозиторий не входят `secrets.h`, `.env`, `storage.json`, установленные библиотеки, `node_modules` и результаты сборки. Вместо ключей и паролей добавлены шаблоны настроек. После клонирования зависимости устанавливаются отдельно, а прошивки собираются под выбранную плату.
